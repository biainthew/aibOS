### **서버 통신은 층으로 분리**


데이터가 서버와 화면 사이를 오갈 때의 역할을 분리


{% raw %}
```plaintext
컴포넌트    →    React Query 훅    →    API 층    →    서버
데이터 요청      캐싱 로딩 에러         URL 정의       HTTP
```
{% endraw %}

- 컴포넌트는 데이터 요청만
- 통신은 API 층 캐싱과 상태는 React Query가 담당
- 한 층만 고치면 되니까 유지보수가 쉬움

### **읽기: useQuery**


서버 데이터를 가져오고 자동으로 상태를 만들어줌


{% raw %}
```typescript
const{ data, isLoading, error}= useReportList();
```
{% endraw %}

- 화면에 뜨면 알아서 서버에서 가져옴
- 로딩, 성공, 실패 세 가지 상태가 있음
- 결과를 queryKey라는 키값을 붙여 캐시에 보관

### **쓰기: useMutation**


데이터를 바꾸는 동작 (생성 삭제 수정)


{% raw %}
```typescript
const del= useDeleteReport();
del.mutate(id); // 버튼 눌렀을 때만 실행
```
{% endraw %}

- useQuery는 화면 뜨면 자동 실행
- useMutation은 `.mutate()`를 부를 때만 실행

### **자동 갱신: invalidateQueries**


바꾼 뒤 목록을 자동으로 새로고침하는 방법


{% raw %}
```typescript
onSuccess:()=> qc.invalidateQueries({ queryKey: reportKeys.list()})
```
{% endraw %}


{% raw %}
```plaintext
삭제 → 서버에서 지움 → 목록 캐시 낡음 선언→ 자동 재요청 → data 바뀜 → 화면 자동 갱신
```
{% endraw %}

- 목록에서 행을 직접 지우는 코드를 안 씀
- 낡았다고 선언만 하면 다시 가져와서 화면이 갱신됨

### **전역 상태: zustand**


여러 컴포넌트가 같이 쓰는 상태는 전역에 둠

- useState는 컴포넌트 안에 갇힌 지역 상태
- zustand는 상태를 전역에 둬서 props 없이 꺼내 쓰고 바꾸게 함

{% raw %}
```typescript
// 필요한 조각만 골라서 구독 (selector)
const document = useReportStore((s) => s.document);
```
{% endraw %}

- selector로 고른 그 값이 바뀔 때만 다시 그림
- set 함수를 부르면 그 상태를 쓰는 컴포넌트가 자동으로 다시 그려짐

### **useEffect**


서버 상태와 편집 상태를 연결할 때 useEffect를 사용

- React Query 상태: 서버에 저장된 원본
- zustand 상태: 지금 편집 중인 내용
- 서버에서 불러온 데이터를 편집 상태로 옮겨야 하는 경우

{% raw %}
```typescript
useEffect(() => {
  if (data) hydrate(data);   // 불러오면 store에 부어넣음
}, [data]);
```
{% endraw %}

- useEffect: 화면을 다 그린 뒤에 실행할 일을 담는 곳
- 두 번째 `[data]`: 이 값이 바뀔 때만 실행하라는 의존성 목록
- 네트워크 요청 외부 상태 변경 같은 부수 작업을 여기서 처리함
