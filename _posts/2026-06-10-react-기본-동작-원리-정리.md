### **명령형 vs 선언형**


리액트 이전 방식과 리액트 방식의 가장 큰 차이는 화면을 다루는 사고방식

- 명령형 (바닐라 JS / jQuery): DOM을 직접 찾아서 바꿈
- 선언형 (React): 상태가 이러면 화면은 이렇다고 선언만 함

{% raw %}
```javascript
// 요소를 찾아서 직접 바꿈
$("#count").text("1");
```
{% endraw %}


{% raw %}
```javascript
// count 값이 바뀌면 리액트가 알아서 화면 갱신
<div>{count}</div>
```
{% endraw %}


### **컴포넌트는 함수**


리액트 컴포넌트는 화면을 만드는 함수


{% raw %}
```javascript
function Hello({ name}){ // props = 부모가 주는 입력
	return<div>안녕{name}</div>; // JSX = 화면 설계도
}
```
{% endraw %}

- props: 부모가 자식에게 내려주는 값
- JSX: HTML처럼 생겼지만 사실은 JS 객체
- 컴포넌트 함수는 화면을 그릴 때마다 다시 실행됨

### **상태(state)**


state는 리렌더를 일으키는 기억 공간


{% raw %}
```javascript
//    현재값 바꾸는함수   초기값
const[count, setCount]= useState(0);
```
{% endraw %}

- 함수는 매번 다시 실행되는데 state 값은 리액트가 따로 보관
- setCount를 부르면 상태 바뀜 리렌더해줘 예약이 걸림
- DOM은 직접 건드리지 않음

### **다시 그리는 흐름**


상태가 바뀌면 화면이 따라오는 과정


{% raw %}
```plaintext
이벤트 발생
→ setState
→ 컴포넌트 다시 실행
→ 새 화면(JSX) 생성
→ 이전과 비교
→ 바뀐 부분만 DOM 갱신
```
{% endraw %}


### **값 넣기와 조건부 렌더**


중괄호로 JS 값을 끼워넣고 조건에 따라 다른 걸 그림


{% raw %}
```javascript
{reports?.length??0} // 값 삽입: 있으면 길이 없으면 0
```
{% endraw %}


{% raw %}
```javascript
{isLoading?<p>불러오는 중</p>:<목록/>} // 조건에 따라 다른 화면
```
{% endraw %}


### **목록 렌더와 key**


배열을 화면 목록으로 바꿀 때 map을 사용


{% raw %}
```javascript
reports.map((r)=>(<Rowkey={r.reportId}>{r.name}</Row>))
```
{% endraw %}

- map: 배열을 JSX 배열로 변환
- key: 각 항목의 고유 표시 리액트가 무엇이 바뀌었는지 추적하는 데 필요

### **이벤트는 콜백으로 넘김**


클릭 같은 이벤트는 함수를 넘겨서 처리함


{% raw %}
```javascript
<buttononClick={()=> setCount(count+1)}>증가</button>
```
{% endraw %}

- `() => ...` 형태로 넘기면 클릭 시 실행이라는 의미
- 화살표 없이 쓰면 화면을 그릴 때 바로 실행돼서 버그가 됨
