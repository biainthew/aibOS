: 운영사가 전기세 낼텐데 금지하는 이유가 뭘까 ?


[https://www.cnbc.com/2026/07/14/new-york-ai-data-center-ban.html](https://www.cnbc.com/2026/07/14/new-york-ai-data-center-ban.html)

2. 공급이 부족해지면 가격이 상승함

>> 그래서 1년간 데이터 센터 운영사가 전력망 증설분에 대한 프리미엄을 지불하거나 자체 발전 설비를 갖추도록 하는 새로운 규제 체계를 마련할 계획


>> 또한 데이터 센터가 노후 전력망 인프라 투자에 직접 기여하도록 기금 신설도 검토중


### GhostApproval


[https://www.wiz.io/blog/ghostapproval-a-trust-boundary-gap-in-ai-coding-assistants](https://www.wiz.io/blog/ghostapproval-a-trust-boundary-gap-in-ai-coding-assistants)

1. 공격자가 악성 repo 를 만들면서 평범한 이름의 파일을 실제로는 `~/.ssh/authorized_keys` SSH 인증키 파일을 가리키는 링크로 위장
2. README 에 이 repo 를 설정하려면 해당 파일을 아래 내용으로 업데이트 하라는 지시문을 넣어둠
3. 피해자가 이 저장소를 클론하고 AI 한테 프로젝트 설정해달라고 하면 에이전트가 README 지시를 따라 해당 파일 업데이트 작업 수행
4. 하지만 실제로는 링크를 따라가 `~/.ssh/authorized_keys` 에 공격자의 SSH 공개키가 심어지고 공격자가 비밀번호 없이 피해자 컴퓨터에 SSH 로 접속할 수 있게 됨

일부 도구에서 AI 에이전트는 내부 추론 과정 중 위험한 파일임을 인식했음에도 사용자에게는 해당 파일을 수정할까요? 라고만 확인창을 띄워 사용자가 무해한 파일을 승인한다고 인식하게 함


이 사례는 AI 에이전트가 사용자에게 확인을 받는다는 안전장치를 갖추고 있어도 그 확인창에 표시되는 정보가 부정확하면 안전장치가 의미없는 행위가 될 수 있다는 점을 보여줌
