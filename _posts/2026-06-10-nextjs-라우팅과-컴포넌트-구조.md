### **폴더 구조 = URL**


Next.js App Router는 app 폴더 구조가 그대로 URL이 됨


| **파일 위치**                   | **주소**         |
| --------------------------- | -------------- |
| `app/page.tsx`              | `/`            |
| `app/reports/new/page.tsx`  | `/reports/new` |
| `app/reports/[id]/page.tsx` | `/reports/123` |

- `page.tsx`: 그 주소에서 보여줄 화면
- 라우팅 설정 파일이 따로 없고 파일 위치가 곧 설정

### **동적 라우트 [id]**


대괄호 폴더는 자리값을 받는 와일드카드


{% raw %}
```typescript
export default async function Page({ params }: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;   // 주소의 그 부분을 꺼냄
  return <Builder reportId={id} />;
}
```
{% endraw %}

- `[id]` 폴더는 `/reports/1` `/reports/abc` 모두 받음
- 그 값이 params로 들어옴

> 💡 **왜 Next.js 는 {id} 를 Promise 로 감쌌는지 ?**  
> Next.js 14 까지는 그냥 객체였지만 15부터 Promise 로 변경됨  
>   
> 원인은 성능이고 지금 당장 필요하지 않으면 페이지의 다른 부분을 먼저 렌더하고 나중에 풀어도 되는 값으로 사용할 수 있게 해줌

### **use client**


컴포넌트가 어디서 실행되는지를 나누는 표시

- 기본값은 서버 컴포넌트로 서버에서 HTML로 만들어 내려보내서 브라우저로 JS가 안 가고 가벼움
- `"use client"`를 붙이면 클라이언트 컴포넌트로 브라우저에서도 실행됨

| **구분**           | **서버 컴포넌트**  | **클라이언트 컴포넌트** |
| ---------------- | ------------ | -------------- |
| useState onClick | 사용 불가        | 사용 가능          |
| 브라우저로 가는 JS      | 없음           | 있음             |
| 사용처              | 정적 화면 데이터 표시 | 클릭 입력 상태 변화    |


{% raw %}
```typescript
"use client";   // 이 줄부터 브라우저에서도 실행

export function Counter() {
  const [n, setN] = useState(0);   // 상호작용은 클라이언트 필요
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}
```
{% endraw %}


### **상태로 화면 제어**


리액트는 화면을 명령으로 열고 닫지 않고 상태로 결정함


{% raw %}
```typescript
// 다이얼로그 열림 여부 = 상태로 결정
<Dialog open={target !== null} onOpenChange={(open) => !open && setTarget(null)}>
```
{% endraw %}

- open이 true면 열리고 false면 닫힘
- 열고 싶으면 setTarget(값) 닫고 싶으면 setTarget(null)
- 다이얼로그를 직접 show hide 하지 않음

### **데이터는 아래로 이벤트는 위로**


제어 컴포넌트의 핵심 규칙

- 상태의 주인은 부모
- 자식은 현재 상태(open)를 받아서 그리기만 함
- 바꾸고 싶으면 부모가 준 함수를 부름
- 닫는 방법이 여러 개여도 결국 상태 하나를 바꾸는 것으로 귀결
